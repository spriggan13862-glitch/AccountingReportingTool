# Alembic Migration Discipline

## Overview

Alembic manages all schema changes after the M21 baseline. Every structural change
to the database — new column, new table, dropped column, index change — must be
captured in a numbered migration file before merging.

## Naming Convention

```
{revision_number}_{slug}.py
```

Examples:
- `001_baseline.py`
- `002_m21_auth_fields.py`
- `003_add_currency_to_accounts.py`

Revision numbers are **sequential integers** padded to 3 digits. Do not use hex hashes
for manually authored migrations — they belong in autogenerated scripts only.

## Common Commands

### Fresh installation

```bash
alembic upgrade head
```

### Existing database (already created by create_all)

```bash
# Mark the DB as at the baseline without running DDL
alembic stamp 001

# Then apply any new migrations that came after the baseline
alembic upgrade head
```

### Create a new migration (autogenerate from model changes)

```bash
alembic revision --autogenerate -m "short description of change"
# Review the generated file before committing — autogenerate is not perfect
```

### Check current revision

```bash
alembic current
```

### View migration history

```bash
alembic history --verbose
```

### Rollback one step

```bash
alembic downgrade -1
```

### Rollback to baseline

```bash
alembic downgrade 001
```

## Rules

1. **Never edit a migration that has been applied in staging or production.**
   Create a new forward migration to correct mistakes.

2. **Always review autogenerated migrations** before committing. Alembic can
   miss computed columns, partial indexes, and check constraints.

3. **Test upgrade AND downgrade** in a local environment before merging.
   The CI pipeline runs both directions on every PR.

4. **Do not use `Base.metadata.create_all()` in production.** It is retained
   in `main.py` only for local development convenience. Alembic is authoritative
   for production schema management.

5. **Add a meaningful docstring** to every migration explaining what changed and why.

## Environment Variables

Alembic reads `DATABASE_URL` from the application settings (`.env` file or environment).
No separate `alembic.ini` database URL is needed — the `env.py` pulls from `app.core.config`.
